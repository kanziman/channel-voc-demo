# PR 자동 생성 스킬 (create-pr)

이 스킬은 현재 작업 중인 브랜치의 변경 사항을 요약하고, 테스트 통과 여부를 검증한 후, GitHub CLI(`gh`)를 활용하여 안정적이고 포맷에 부합하는 Pull Request를 자동으로 게시하도록 강제합니다.

> **선행**: [`.claude/skills/_shared/stack-and-conventions.md`](../_shared/stack-and-conventions.md)를 먼저 읽어 스택([BE]/[FE])과 브랜치/Base 규칙을 확정한다.

## 사용법

- 명시적 호출: `/create-pr [GitHub 이슈 번호]` (예: `/create-pr 1`)
- 자연어 트리거: "PR 만들어줘", "PR 올려줘", "PR 보내줘", "이거 머지하자", "create-pr" 등의 요청 시 자동 실행

## 입력 인자

- `$ARGUMENTS`: GitHub 이슈 번호 (선택 사항이며, 제공된 경우 PR 본문에 이슈 연결 코드가 자동 삽입됩니다)

---

## 📌 상세 실행 단계

이 스킬이 가동되면 다음 5단계를 순서대로 엄격히 수행합니다.

### 1단계: 변경 사항 분석 및 PR 초안 작성

- **동작**:
  - `git status` 및 `git diff`를 실행하여 작업 공간의 수정 및 추가 사항을 면밀히 분석합니다.
  - 이를 요약하여 **PR 제목**과 **PR 본문(Body)** 초안을 Markdown 형식으로 작성합니다.
  - **이슈 종결 구문 주입**: 입력 인자 `$ARGUMENTS`가 있는 경우, 본문 하단에 반드시 **`Closes #$ARGUMENTS`** 구문을 포함하여 머지 시 관련 이슈가 자동으로 닫히도록 연결합니다.
  - **Base 브랜치 자동 탐색** (공용 규약 §3): 자식 브랜치는 `<부모>-issue-<N>` 형태이므로, 현재 브랜치명에서 `-issue-<N>` 접미사를 제거한 것이 부모(Base) 브랜치(예: `phase3/design-tokens-issue-6` → `phase3/design-tokens`)입니다. 원격에 그 부모 브랜치가 있는지 확인해 Base로 설정합니다.

### 2단계: 개발자 검토 및 초안 승인

- 생성된 PR 제목, Base 브랜치, 본문 초안을 개발자에게 보여주고 **검토 및 승인**을 요청합니다.
- 개발자가 피드백을 주면 초안을 수정하며, 최종 컨펌이 날 때까지 **대기**합니다.

### 3단계: 테스트 실행 및 검증 (스택별)

- 개발자의 승인을 얻으면, 테스트 검증 단계에 돌입합니다.
- **[BE] 백엔드/API 변경**: E2E가 없으므로 **`pytest -q` 전체 통과**를 게이트로 사용합니다. (특히 API 왕복 시나리오·회귀 테스트가 초록인지 확인)
- **[FE] `web/` 변경**: `cd web && npm run test:e2e`로 Playwright E2E 전체를 검증합니다. 단, 아직 E2E 대상 화면이 없으면 이 단계를 건너뛰고(pass) `cd web && npm test`(단위) 통과로 대체합니다.

### 4단계: E2E 실패 시 대처 및 복구 지침 (중요)

- 만약 3단계 테스트 중 하나라도 실패하는 경우, **PR 생성을 즉시 중단**하고 개발자에게 에러 요약을 보고한 뒤 아래의 **복구 가이드라인을 준수**하여 다음 단계 처리를 유도합니다.
  - **실패 복구 프로세스**:
    1. **재현/디버깅**: [FE] `cd web && npx playwright show-report`로 깨진 시나리오를 확인 / [BE] 실패한 `pytest` 노드를 `-x -vv`로 재현합니다.
    2. **원인 분석**: 오류가 API 레이어, UI 렌더링 레이어, 혹은 핵심 비즈니스 로직 레이어 중 어디서 기인했는지 식별합니다.
    3. **단위 테스트 케이스 추가 (Red)**: 식별한 실패 시나리오를 검증하는 단위 테스트를 관련 파일([BE]`tests/test_*.py` / [FE]`*.test.ts(x)`)에 추가하여 실패하게 만듭니다.
    4. **프로덕션 코드 수정 (Green)**: 단위 테스트가 통과하도록 소스 코드를 교정합니다. 통과 후 다시 `/create-pr`을 호출합니다.
  - ⚠️ **주의사항**: **절대 테스트 코드 자체를 인위적으로 고쳐서 강제 통과시키지 마십시오.** 이는 근본 원인을 회피하는 위험한 우회입니다.

### 5단계: 코드 푸시 및 Pull Request 생성

- 3단계 테스트가 100% 정상 통과하면 다음을 수행합니다.
  - **커밋 메시지 검사**: 최종 커밋 메시지가 conventional commit 포맷(feat, fix, refactor 등 접두사 및 소문자 규칙)에 부합하는지 검사합니다.
  - **Push**: `git push origin [현재브랜치명]`을 수행합니다.
  - **PR 생성**: GitHub CLI를 사용하여 PR을 발행합니다.
    - 커맨드: `gh pr create --title "[PR 제목]" --body "[PR 본문]" --base [부모브랜치명]`
  - **이슈 피드백**: 생성된 PR의 주소(URL)를 획득하여 관련 GitHub 이슈에 PR 링크를 포함하는 완료 댓글(Comment)을 작성하고 전체 스킬의 실행을 마칩니다.
