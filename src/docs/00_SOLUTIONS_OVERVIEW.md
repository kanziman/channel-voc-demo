## 📌 문서 목적
본 문서는 채널톡(채널코퍼레이션)의 공개 자료, 대표 인터뷰(인재밀도, 본질 탐구, 이커머스 이탈 방지), 및 이커머스/CS 커뮤니케이션 시장 리서치를 기반으로 도출된 **3가지 엔터프라이즈급 Codex 플러그인 솔루션 후보**를 비교·분석합니다. 

각 보고서는 **3~4주 개발 공수 수준의 비즈니스 문제 해결 아키텍처**를 담고 있으며, 단일 보고서 읽기만으로도 문제 정의부터 시스템 구조, 검증 방안까지 전 과정을 이해할 수 있도록 구성되었습니다.

### 종합 추천

- **단독 제출 1순위 → Idea 2 (CX-to-Dev Root Cause Loop)**: 입력(대화 텍스트)과 출력(GitHub Issue/PR)이 모두 Codex의 본령이라 **실제 작동을 데모로 증명**하기 가장 쉽고, "왜?의 본질 탐구 + 10배 인재밀도" 인터뷰 서사와도 정확히 맞물림.
- **임팩트 데모 지향 대안 → Idea 1 (이탈 회복)**: "방어 매출"이라는 ROI가 가장 직관적. 단 실시간 행동 훅을 버리고 "이탈 대화 로그 → 원인분류 → 회복 메시지" MVP로 축소 필수.
- **Idea 3**: 비전은 최고이나 시계열 이탈 예측 특성상 4주·단발 데모 실증이 가장 어려움 → 장기 로드맵/후속 과제로 배치 권장.

### 3개 공통 필수 보완 (제출 전 체크리스트)

1. **데이터 정직성**: 출처 미확인 수치(Idea1 원인비율, Idea2 35~40%·4.2일, Idea3 Bain 재해석)를 검증·인용하거나 "가정"으로 재라벨링.
2. **MVP/비전 분리**: 실제 시연 범위와 확장 로드맵을 문서에서 명확히 구분.
3. **검증 탈순환화**: 자기생성 데이터셋 → held-out·사람 라벨·블라인드 평가로 전환.
4. **채널톡 실연동 표면 명시**: Open API/Webhook 기준으로 "재발명"이 아닌 "플러그인"임을 증명.
