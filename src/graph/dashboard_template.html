VOC 인텔리전스 부서 · LangGraph · Neo4j · GraphRAG

증상이 아니라,
근본 원인을 배포한다

실제 고객상담 1,200건을 Neo4j 지식그래프로 엮는다. 증상 → 컴포넌트 → 반복 루트원인을 순회하고, 선례를 인용해 GitHub 이슈를 만들고, 사람 승인에서 멈춘 뒤 — 실제로 배포한다.

01

대화 한 건이 이슈가 되기까지

상담 한 건이 6단계를 지나 배포된 이슈가 된다. 단계를 클릭하거나 ▶ 재생을 누르면 원본 → 추출 → Cypher → 집계 → GraphRAG → 승인 → 배포를 눈으로 따라간다.

02

은유가 아닌, 진짜 에이전트

SQLite 체크포인터 · 조건부 엣지 · 진짜 interrupt() 승인 게이트를 갖춘 LangGraph StateGraph. 강조된 노드가 이번 실행 경로, 주황색 노드가 사람이 멈춘 지점이다.

03

부서가 일한 기록

각 노드가 무엇을, 얼마나 빨리 했는지 스스로 보고한다.

04

루트원인은 라벨이 아니라 집계

여러 대화가 독립적으로 지목한 컴포넌트가 루트원인이 된다. 루트원인 노드를 클릭하면 근거 대화 → 증상 → 컴포넌트 → 이슈로 이어지는 ₩ 경로가 켜진다.

인터랙티브 지식그래프

드래그로 재배치 · 루트원인을 클릭하면 ₩ 경로가 켜진다.

05

모든 문장이 실제 대화를 인용

GraphRAG가 벡터 + 그래프 하이브리드로 정확한 대화 id를 찾아 이슈 초안을 쓴다. 카드를 펼치면 유사도와 검색 출처가 붙은 근거가 나온다.

06

하이브리드 검색, 직접 해보기

쿼리를 입력하면 세 갈래로 채점된다 — Dense(의미, bge-small 384d) · Sparse(키워드, Neo4j 풀텍스트) · Graph(구조적 이웃) — 그리고 RRF로 융합. [📄 원문 보기]로 대화 전문까지 확인한다.

07

업그레이드를 숫자로 증명

같은 held-out 600건, 같은 27-class 인텐트 과제를 Cohen's κ로 채점.

08

돈이 새는 길목

컴포넌트별 매출 위험액(₩)이 배포됨(실제 이슈) 또는 검토 대기(게이트 미만)로 흐른다. ₩는 투명한 PHASE1 가정 모델로 계산.
